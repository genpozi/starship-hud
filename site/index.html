The demo is the real HUD, built and served as static files. With no orbit server reachable it falls back to its built-in offline simulation on seed data — every panel is live and clickable, but the numbers are synthetic. Run it locally with an orbit server to drive it for real.

What it is, and what it isn't

What it is

  • A working orchestrator: six agents with state machines, retry policies, and typed tools.
  • Superstep DAG scheduling — a step starts only when every dependency is complete.
  • Real transport: WebSocket snapshot/delta with sequence numbers, gap detection, and resync.
  • Checkpoints, rollback, single-holder interrupt, and span-level trace telemetry.
  • A headless test suite per subsystem, including a full REST + WebSocket integration suite.
  • Optional live integrations: GitHub, Hermes WebUI, an LLM planner, and Gmail/Graph/ICS/CalDAV comms.

What it isn't

  • Not a hosted service. There is no account, no billing, and no cloud backend.
  • Not a real starship. The HUD is a deliberate interface metaphor for observability.
  • Not a distributed system. One orbit server process owns the state; it is single-node.
  • Not an LLM product by default. The planner is a deterministic heuristic unless you supply a key.
  • No IMAP/SMTP, no GitHub issue write-back, no binary attachment download.
  • The demo is seed data, not your data.

Checkpoints and rollback

A boot-guard snapshot plus on-demand full-state captures in a capped ledger. SNAP and REWIND restore state and report which slices were reverted.

server/checkpoints.js

P11

Single-holder interrupt

Pause halts dispatch while in-flight steps finish. A second operator receives 409 until the holder resumes.

server/orchestrator.js

P12

Span traces

Every run and tool call records a span with duration and token accounting, streamed as typed events into the Health view.

server/trace.js

P9

Typed event channels

Non-state frames fold through client-side reducers. Unknown frame types are ignored, so a newer server never breaks an older client.

src/channels.js

P14

Filesystem knowledge vault

Markdown with front matter on disk. Writes hit the file first, then state; boot hydrates files back onto the state slice.

server/vault.js

Architecture

FIG. 05 — SINGLE SOURCE OF TRUTH

Browser (Vite SPA)                 Orbit server (Node, :3001)
+----------------------+    WS    +--------------------------------+
| src/main.js   boot   |<-------->| server/index.js   express + ws |
| src/store.js  state  |   /ws    | server/orchestrator.js  engine |
| src/views.js  views  |   REST   | server/planner.js  LLM/heuris. |
| src/api.js    bridge |  /api/*  | server/skills.js   tool reg.   |
| src/channels.js typed|          | server/trace.js    span tree   |
| src/galaxy.js 3D bg  |          | server/checkpoints.js snapshots |
| src/config.js seed   |          | server/store.js    persistence |
+----------------------+          | server/vault.js    md files    |
                                  | data/state.json + vault/*.md   |
                                  +--------------------------------+

The orbit server owns canonical state. The browser mirrors it over WebSocket and mutates it over REST. If the server is unreachable the HUD switches to the offline simulation described above.

Quickstart

FIG. 06 — NODE 20+, ZERO EXTERNAL SERVICES

# 1. Install dependencies
npm install

# 2. Orbit server: REST + WebSocket on :3001, owns fleet state
npm run dev:server

# 3. In a second terminal: Vite dev server on :5173
npm run dev

Production: npm run build then npm start. Or the packaged CLI: npx stellaris-hud serve.
